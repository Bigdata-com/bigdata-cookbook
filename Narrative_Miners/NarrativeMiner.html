Narrative Miners: Uncover the Stories That Drive Markets¶

Automated Analysis of Market Narratives Across Multiple Document Sources¶

Why It Matters¶

Understanding how market narratives emerge and evolve across different information sources is crucial for investment decision-making, but manually tracking narrative development across scattered news coverage, earnings calls, and regulatory filings is time consuming. Investment decisions need systematic analysis of narrative progression to identify emerging trends and timing patterns.

What It Does¶

This cookbook systematically tracks narrative evolution across multiple document types using unstructured data from news, transcripts, and filings, retrieved via the Bigdata.com REST API and bigdata-smart-batching. Built for analysts, portfolio managers, and investment professionals, it transforms scattered narrative signals into quantified trend intelligence and identifies timing patterns across different information sources.

How It Works¶

The pipeline combines multi-source content retrieval (REST search across a small company universe), OpenAI-based narrative labeling, and cross-source comparative analysis to deliver:

  • Cross-document narrative mapping across news media, earnings calls, and SEC filings
  • Temporal evolution tracking showing how narratives develop and change over time across sources
  • Intensity measurement quantifying narrative prevalence and significance across document types

A Real-World Use Case¶

This cookbook demonstrates the complete workflow through analyzing "AI Bubble Concerns" narrative as it emerges and evolves across news, earnings calls, and regulatory filings, highlighting the difference between public discourse and corporate communications. The universe used is the "Magnificent Seven" mega-cap tech companies (../Thematic_Screener_CLI/mag7.csv), the natural subjects of AI-bubble commentary.

Define Labeling Helpers¶

Define the OpenAI structured-output narrative classifier and a small converter that reshapes run_universe_search() output into the schema src/tool.py expects (Date, Label, Sentence ID, Headline, Chunk Text).

In [9]:
from enum import Enum

from pydantic import BaseModel

from src.llm_helpers import DEFAULT_LLM_MODEL, sampling_params_for_model


class NarrativeLabel(str, Enum):
    VALUATION_DISCONNECT = "Valuation Disconnect"
    ROI_SKEPTICISM = "ROI Skepticism"
    INVESTMENT_SURGE = "Investment Surge"
    REGULATORY_RISK = "Regulatory Risk"
    BUBBLE_COMPARISON = "Bubble Comparison"


class NarrativeClassification(BaseModel):
    label: NarrativeLabel


def label_with_openai(client, text, model=llm_model or DEFAULT_LLM_MODEL):
    """Classify a single chunk of text into one of the AI-bubble narrative buckets."""
    completion = client.beta.chat.completions.parse(
        model=model,
        messages=[
            {
                "role": "system",
                "content": (
                    "Classify the AI-bubble narrative expressed in the following text "
                    "snippet into exactly one label."
                ),
            },
            {"role": "user", "content": text[:600]},
        ],
        response_format=NarrativeClassification,
        **sampling_params_for_model(model, temperature=0.0),
    )
    return completion.choices[0].message.parsed.label.value


def build_narrative_df(raw_df, client, source_type, max_openai_labels=max_openai_labels):
    """Convert run_universe_search() output into the schema tool.py expects.

    A capped number of rows are labeled via an OpenAI call; the rest fall back to the
    matched narrative query text so the OpenAI spend stays bounded regardless of how
    many chunks REST search returns.
    """
    columns = ["Date", "Label", "Sentence ID", "Headline", "Chunk Text", "Source_Type"]
    if raw_df.empty:
        return pd.DataFrame(columns=columns)

    rows = raw_df.reset_index(drop=True)
    labels = []
    for i, row in rows.iterrows():
        if i < max_openai_labels:
            try:
                labels.append(label_with_openai(client, row["chunk_text"]))
            except Exception as exc:
                print(f"  ⚠️ OpenAI labeling failed for row {i}: {exc}")
                labels.append(row["query"][:60])
        else:
            labels.append(row["query"][:60])

    out = pd.DataFrame(
        {
            "Date": pd.to_datetime(rows["timestamp"], errors="coerce", utc=True).dt.tz_localize(None),
            "Label": labels,
            "Sentence ID": [f"{doc_id}_{i}" for i, doc_id in enumerate(rows["document_id"])],
            "Headline": rows["headline"],
            "Chunk Text": rows["chunk_text"],
        }
    )
    out = out.dropna(subset=["Date"])
    out["Source_Type"] = source_type
    return out

The Narrative Miners reveal important patterns in how the AI bubble narrative evolved across information sources:

Timing and Intensity Variations:

  • News media shows major spikes in AI bubble concerns, often leading the narrative cycle with the highest peaks
  • Earnings calls demonstrate cyclical attention to bubble concerns, with executives addressing topics most prominently during specific quarters
  • SEC filings show the most volatile pattern with multiple significant spikes, suggesting ongoing regulatory concerns

Narrative Progression:

  • Media coverage often leads the initial bubble narrative, potentially triggering corporate responses visible in earnings calls
  • Corporate executives' discussions peak during specific periods but tend to diminish over time
  • SEC filing mentions frequently show increased intensity throughout the analysis period, indicating persistent regulatory attention

Cross-Source Intelligence:

  • Different sources provide complementary perspectives on the same underlying narrative
  • Timing lags between sources reveal information flow patterns and decision-making hierarchies
  • The intensity patterns help identify when narratives are gaining or losing momentum across different stakeholder groups

This analysis demonstrates how systematic narrative mining across multiple document types provides richer insights than analyzing any single source in isolation.
